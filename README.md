# GymSpringApp
GymApp is backend implementation of a microservice-based gym management system built with Spring Boot and Spring Cloud Gateway

## Data Structure
There are 3 main data object Gym, Membership and Member
Member is part of Membership, membership is a part of Gym

## Architecture
App is divided into 4 microservice modules:
- Gateway service
- Gym service
- Membership service
- Member service

Gateway service acts as an API Gateway that routes HTTP requests.

Gym, Membership and Member services are built of such elements:
- GymApplication.java - main class
- entity package - contains entities of Gym/Memebrship/Member objects as well as local reference model of the object they directly belong to named as Category (e.x. Membership service own simplified representation of Gym Object - Category.java)
- repository package - contains JPA repositories of enitities
- service package - service layer that contains business logic and coordinates repository access
- dto package - contains Data Transfer Objects used in App
- mapper package - contains mappings of DTOs to Entities and Entities to DTOs
- controller - contains REST API controllers
- config(not in every service) - contains configuration for REST communication (RestTemplate)
- exception(not in every service) - contains custom exceptions used by service

## Tech Stack

- Java 17
- Spring Boot 3.2.0
- Spring Cloud Gateway 2023.0.2
- Spring Data JPA
- H2 Database (in-memory)
- Lombok
- Maven (multi-module project)

## Testing 
Service layer tests are written using JUnit 5 and Mockito (provided via Spring Boot Starter Test)

## How to run the project

This is a backend-only microservices application. The system can be tested using the `communicationTesting.http` file located in the Gateway service resources. The IDs in the example requests should be changed to appropriate IDs generated by the previous requests

To test the system:
1. Start all microservices and API Gateway
2. Use communicationTesting.http with appropriately changed IDs
